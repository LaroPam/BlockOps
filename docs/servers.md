# Итерация 2: управляемый Vanilla-сервер

Реализованы `crates/server-manager` (библиотека и CLI) и команды/экраны Tauri для
установки, списка независимых серверов, запуска, остановки, консоли и создания
приглашения к работающему серверу. Поддерживаются **Vanilla 1.21.1 и 1.21.4 / Java 21**. Это намеренно ограниченный
список проверяемых версий; другие версии и загрузчики пока не доступны.

## Установка и данные

1. Пользователь самостоятельно читает Minecraft EULA и явно принимает её для сервера.
   Checkbox изначально выключен; CLI требует `--accept-eula`. Без принятия загрузки не начинаются.
2. Resolver получает официальный Mojang version manifest, проверяет SHA-1 version metadata,
   выбранный release ID, Java major=21 и опубликованные размер/SHA-1 серверного JAR.
3. Официальный Adoptium API выбирает Eclipse Temurin JRE 21 для Windows/Linux x86_64.
   Архив проверяется по SHA-256 и размеру до распаковки. HTTPS проверяется системными CA.
   Redirects ограничены разрешёнными официальными HTTPS-хостами.
4. ZIP/TAR распаковываются в staging с ограничением количества записей и общего размера.
   Path traversal, абсолютные ссылки, специальные файлы и ссылки за пределы staging запрещены.
   Проверяется `java -version`; готовый runtime устанавливается переименованием каталога.
5. Каждый сервер получает UUID-каталог с JAR, properties, eula.txt и миром. SQLite хранит
   имя, настройки, версию, SHA-1 JAR и время принятия EULA. Runtime общий, данные миров раздельные.

Установка защищена файловой блокировкой; запущенный сервер держит отдельную блокировку
против дублирующего запуска из другого процесса. Сбой процесса между переименованием
каталога и записью SQLite может оставить неиндексированный каталог: автоматический recovery
таких сирот ещё не реализован. Неполная установка не показывается готовым сервером.

Desktop использует Tauri `app_data_dir`; CLI принимает явный `--data-dir`. Никогда не храните
JAR, runtime или миры в Git. Первая установка загружает сотни мегабайт. На каждого нового
сервера нужно отдельное место для мира и доступная RAM; текущая проверка ограничивает
настройку RAM диапазоном 1024–16384 МиБ, но ещё не рассчитывает суммарный бюджет компьютера.

## Проверка из CLI

```sh
cargo build --workspace --locked
# Сначала самостоятельно прочитайте https://www.minecraft.net/eula.
# Только если вы принимаете условия:
target/debug/blockops-server-manager --data-dir /private/blockops-data install \
  --name 'Мой мир' --memory-mb 2048 --port 25565 --accept-eula

target/debug/blockops-server-manager --data-dir /private/blockops-data list
# Подставьте ID из ответа install/list:
target/debug/blockops-server-manager --data-dir /private/blockops-data run SERVER_UUID
```

`run` печатает реальные состояния и последние строки stdout/stderr. Ctrl+C отправляет
Minecraft команду `stop`, ждёт сохранения мира; через 30 секунд допускается принудительное
завершение с явной ошибкой. Принудительное завершение не считается безопасным backup.

В другом терминале, после сообщения Minecraft `Done`:

```sh
python3 scripts/minecraft_smoke.py --port 25565
```

Проверка обращается к настоящему Minecraft напрямую и через отдельные процессы host,
relay и guest. Проверяются JSON status, версия/номер протокола и ping/pong nonce.
Скрипт **не принимает EULA, не запускает Java и не выполняет вход аккаунта игрока**.
Он убирает созданные туннели и relay. Minecraft останавливается отдельно через Ctrl+C.

## Безопасные настройки и жизненный цикл

Сервер привязан к `127.0.0.1`; online-mode и enforce-secure-profile включены. RCON/query
выключены. RAM, сложность, число игроков и порт задаются при создании. JAR повторно
проверяется перед запуском. Менеджер понимает перестановку properties/дополнительные
значения, записанные Minecraft, но отказывает при изменении управляемых параметров,
дубликатах и неоднозначном синтаксисе. Ручное редактирование управляемых настроек пока
не поддерживается. Отзыв `eula=true` блокирует следующий запуск.

Desktop разрешает приглашение после реального сообщения о готовности. При завершении
управляемого Java-процесса закрывается только относящаяся к его generation сессия туннеля.
При нормальном закрытии окна ожидается остановка серверов; аварийное завершение ОС
всё равно может прервать сохранение. Консоль ограничена 200 строками по 8 КиБ.
Состояние `running` обозначает завершение загрузки мира, а не проверку входа аккаунта.

## Сетевые требования и установленное ограничение cloud

Загрузки: piston-meta.mojang.com, piston-data.mojang.com, api.adoptium.net,
github.com, release-assets.githubusercontent.com. Аутентификация Minecraft требует
api.minecraftservices.com и sessionserver.mojang.com.

Rust HTTPS downloader использует системное доверие сертификатам и HTTPS_PROXY.
JVM получает credential-free HTTP CONNECT proxy из HTTPS_PROXY и, на Debian/Linux,
системное Java-хранилище CA, если оно доступно. Проверки TLS не отключаются; переменные
JAVA_TOOL_OPTIONS/JDK_JAVA_OPTIONS/_JAVA_OPTIONS/CLASSPATH не наследуются сервером.
Однако **Vanilla 1.21.1 явно передаёт Proxy.NO_PROXY в authlib**, поэтому глобальный JVM
HTTPS-прокси не исправляет его запросы аутентификации. В текущем cloud-контейнере эти
запросы завершаются UnknownHostException: прямой DNS недоступен. Это показано в диагностике.
Нужна среда с работающим поддерживаемым прямым доступом Minecraft к этим сервисам.
Мы не меняем authlib, не подменяем криптографию и не выключаем online-mode.

## Проверено в текущем Linux-окружении

- Официальные загрузки, проверки SHA-1/SHA-256, распаковка Temurin 21.0.13+9.
- Vanilla 1.21.1 создал мир, перешёл в running, ответил через relay, сохранил все
  измерения по stop и успешно запустился повторно после перезаписи properties Minecraft.
- Unit/integration проверки настроек, EULA gate, хешей, архивов, SQLite, блокировок,
  жизненного цикла, ограничений вывода и диагностики аутентификации.
- Windows GUI/установщик и публичный NAT не проверены. Нативная Tauri-сборка в этом
  контейнере по-прежнему блокируется отсутствующими GLib/GTK/WebKit dev libraries.

Следующий срез: проверить Windows UI/установщик и вход лицензированного игрока,
затем coordination API для одноразовых коротких кодов, привязка к identity гостя,
персональный отзыв и контролируемый публичный relay. Backup и другие загрузчики — позже.


## Резервные копии и изменение настроек

Настройки остановленного сервера можно изменить в приложении: название, RAM, порт,
сложность и максимум игроков. Дополнительные свойства Minecraft сохраняются;
`online-mode=true` и loopback сохраняются обязательно. Запись согласовывает SQLite и
файл properties через журнал; прерванная операция восстанавливается при следующем
запуске или изменении настроек.

Резервная копия создаётся только для остановленного управляемого сервера и содержит
каталог мира, включая пустые каталоги. Для каждой записи сохраняется SHA-256; при
восстановлении содержимое проверяется в отдельной staging-папке. Предыдущий мир
сохраняется как `world-before-restore-<UUID>` в каталоге сервера. Сохраняйте копии
на отдельном носителе: локальная копия не защитит от отказа диска. Хеши обнаруживают
повреждение, но не подтверждают происхождение изменённого архива. Ограничения: до
50 000 записей и 20 ГиБ распакованных данных; автоматического расписания и удаления
старых копий нет. Дополнительно требуется место для копии и сохранённого старого мира.
Блокировка защищает от одновременно запущенного через BlockOps сервера, но не от
внешней программы, которая отдельно изменяет эти файлы.

При прерывании замены marker блокирует запуск. В разделе «Резервные копии» доступна
проверка и восстановление состояния; при неоднозначности файлы сохраняются для ручной
проверки. CLI: `backup SERVER_UUID`, `list-backups SERVER_UUID`,
`restore SERVER_UUID BACKUP_UUID`, `recover-restore SERVER_UUID` после параметра
`--data-dir`. Восстановление заменяет выбранный мир и сохраняет предыдущий.

## Консоль

В карточке запущенного сервера откройте «Консоль», введите команду Minecraft и нажмите
«Отправить». Ответ отображается в журнале сервера. Поле доступно локальному владельцу
приложения, а не участникам игрового туннеля. Ввод ограничен одной строкой и очередью
команд; результат записи означает доставку в stdin, не гарантию выполнения Minecraft.
Для остановки используйте отдельную кнопку: она показывает состояние «Останавливается»
до завершения сохранения мира. При закрытии приложения остановка продолжается.
Если запись в консоль не завершилась вовремя, сервер принудительно останавливается и
приложение сообщает о необходимости проверить целостность мира.


## Версия сервера

Версия выбирается при создании сервера; существующие миры остаются на своей версии.
CLI `install` принимает `--version 1.21.1` или `--version 1.21.4` (по умолчанию
1.21.1). Другие версии отклоняются до скачивания. Для каждой установки требуется отдельное
явное принятие EULA; установленный архив проверяется перед каждым запуском. Резервную
копию нельзя восстановить на сервер с другой версией. Автоматическое обновление мира
и переход между версиями пока не реализованы.

Метаданные и JAR 1.21.4 скачаны из Mojang и проверены по размеру/SHA-1, требование Java
21 подтверждено. После отдельного принятия пользователем EULA сервер 1.21.4 запущен,
проверен через одноразовый код и relay и штатно остановлен с сохранением мира.
Проверка входа лицензированного игрока и Windows GUI остаются невыполненными.

## Список допуска

Для нового или остановленного сервера можно включить «Разрешать вход только игрокам из
списка допуска». Настройка применяется при следующем запуске. Пустой список не пускает
обычных игроков; операторы сервера сохраняют доступ. Существующие серверы, созданные
до появления этой настройки, сохраняют прежнее значение: список допуска выключен.

После запуска в разделе «Список допуска» можно отправить серверу команду добавления,
удаления или просмотра. Укажите имя игрока Minecraft Java: от 1 до 16 латинских букв,
цифр и знаков подчёркивания. Команды выполняет сам сервер; ответ смотрите в консоли.
Сообщение «команда отправлена» подтверждает передачу в stdin, а не успешное добавление.
Для разрешения имени серверу может потребоваться доступ к сетевым службам Minecraft.
BlockOps не запрашивает учётные данные и не проверяет лицензию игрока.

`online-mode=true` и loopback-адрес сервера сохраняются. Для CLI при создании доступен
флаг `--whitelist`, а `update-settings` требует явное `--whitelist true` или
`--whitelist false`, чтобы не менять настройку случайно.
