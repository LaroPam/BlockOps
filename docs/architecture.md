# BlockOps: архитектура и границы первой итерации

## Осуществимость

Minecraft Java использует TCP: локальный endpoint гостя можно соединить с фиксированным
endpoint сервера через multiplexed libp2p stream. Клиент Minecraft сохраняет штатную
аутентификацию; online-mode=true обязателен. Minecraft Bedrock/UDP, голосовые моды,
LAN discovery и произвольный VPN в этот прототип не входят.

Два пользовательских сценария конечного продукта: «Создать сервер» и «Присоединиться».
Первая итерация предоставляет диагностический desktop shell и работающий туннель к
уже запущенному TCP-сервису. Она не выдаёт туннель за менеджер Minecraft.

## Компоненты

- apps/desktop: React/TypeScript + Tauri 2. Rust-команды принимают типизированные
  параметры; shell execution и файловый доступ из webview не предоставляются.
- crates/tunnel: общий Rust API и CLI host/join; Tokio, rust-libp2p, Noise, Yamux,
  circuit relay v2, identify, DCUtR. Один stream на TCP-соединение, backpressure
  средствами copy_bidirectional. Получатель проверяет capability перед открытием target.
- crates/relay: отдельный публичный circuit relay. Он пересылает зашифрованный поток,
  не знает capability и не завершает сквозной Noise-сеанс host/guest.
- Будущие компоненты: server-manager, Java/component resolver, SQLite repository,
  backup worker и coordination API для коротких одноразовых кодов.

## Доверие и ограничения

Invite прототипа — JSON capability с 256-битным случайным токеном, PeerId хоста,
адресом транспорта и сроком действия. Это секрет: не публиковать в логах/репозитории.
PeerId привязывает Noise handshake к ожидаемому хосту. Сравнение токена constant-time.
Гость слушает только loopback; target хоста тоже только loopback и неизменен в сессии.
Удалённый участник не выбирает адрес/порт назначения и не получает файловый API.
Хосту следует выбирать только порт Minecraft: туннель передаёт TCP и не анализирует
Minecraft protocol. LAN адреса и wildcard bind отклоняются.

Остановка сессии отзывает приглашение и закрывает активные соединения. Персональные
учётные записи, выборочное отключение, одноразовое погашение, безопасное хранение
identity и автоматическое восстановление активной игры — следующий этап. Приглашение
сейчас многоразовое до expiry; истечение блокирует новые соединения, текущая игра
продолжается до остановки сессии. Capability не заменяет Minecraft authentication.

Relay необходим при CGNAT; доступность NAT traversal без публичной инфраструктуры
не гарантируется. DCUtR включён, но публичные NAT-сценарии отдельно не подтверждены.
Нет обещания бесшовного восстановления TCP после сетевого разрыва. Новый TCP-клиент
может открыть новый stream; игровому клиенту потребуется переподключение.

## Управление серверами: следующий вертикальный срез

Сначала Windows + Vanilla одной версии: проверяемые HTTPS manifest/download официального
Mojang, подбор официального Java runtime, проверки опубликованных хешей, staging и atomic
rename, явное принятие Minecraft EULA до записи eula=true. Не включать JAR в установщик.
Сохранять online-mode=true. SQLite хранит metadata и состояния, отдельные каталоги
серверов, ограничение RAM, process supervisor с graceful stop, консоль и backup после
save-all flush. Затем coordination API выдаёт короткий временный код, с rate limiting,
однократным погашением и привязкой к identity гостя, отзывом и аудитом без секретов.

Paper/Fabric/Forge/NeoForge требуют самостоятельных adapters с проверяемыми metadata,
установщиками и совместимостью Minecraft/Java/loader. Не представлять их простым выбором
JAR URL. Для Windows нужны CI сборка, установщик NSIS/MSI, подпись, проверка Defender,
обновления с подписью, лимиты диска и recovery после сбоя.

## Риски и проверки

Relay оплачивает оба направления трафика; нужны квоты на identity/сессию, длительность,
байты и глобальный bandwidth, наблюдаемость и admission control перед публичным сервисом.
Базовый relay libp2p ограничивает reservations/circuits; его defaults не являются
production billing или защитой от распределённого злоупотребления.
Интеграционные тесты проверяют direct и принудительный relay, двусторонние байты,
отклонение capability и остановку. Linux проверяет сетевое ядро; Windows desktop,
публичный NAT/CGNAT, настоящая Minecraft-сессия и установщик требуют отдельной проверки.

## Итерация 3

Добавлен отдельный HTTP coordinator и локальный per-member ACL туннеля. Одноразовый код
погашается атомарно, затем хост связывает grant с Noise PeerId гостя. Отзыв необратим и
закрывает активные streams; потеря coordinator закрывает доступ. Текущая модель доверяет
coordinator, хранит записи только в памяти и не включает учётные записи.
Контракты, риски и развёртывание: [координация](coordination.md).
